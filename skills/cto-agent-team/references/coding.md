# Ponytail for coding and review

Use the core `ponytail` skill for coding, fixes, refactoring, dependency decisions, and code review. Find it through the current skill catalog and read its actual content. The [upstream core skill](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md) is the reference. This routing guide does not replace it. Use `full` guidance by default. `lite`, `full`, and `ultra` describe skill behavior, not model reasoning or speed settings.

This applies to the CTO, every PM, and every engineer when doing applicable work. New or resumed agent handoffs must include the actual core skill reading requirement for that work. Read it once per relevant context; reuse recorded source/version evidence and reread only when needed or the source changes. An installation or role reference does not prove a particular chat has read it. Keep all roles focused on useful reuse, complete outcomes, concise results, and necessary tool calls. Mechanical supervisors need not reload the skill on each tick or perform code review.

Trace the affected behavior and callers before choosing a change. Prefer the project's existing components and helpers, standard platform capabilities, and installed dependencies. Deliver the complete requested behavior with the least unnecessary complexity. Preserve required validation, error handling, security, accessibility, data integrity, hardware calibration, and meaningful tests. Keep checks proportional and reuse successful evidence for unchanged inputs. Do not turn this preference into recurring whole-repository audits or optional abstractions.

For UI coding, apply [Emil's design guidance](ui-design.md) alongside Ponytail. One guides the interface decisions, the other reduces unnecessary implementation. Neither changes authorization, model settings, resource ownership, ASD-STE100 handoffs, rapid intake, useful parallel work, or completion follow-up. Honor later user overrides.

A standalone core skill can supply the guidance without a host-specific plugin. Discover or install it through the available authorized skill workflow, reusing any existing installation owner. Do not make Claude Code dashboards, hooks, session-log import, telemetry, slash commands, or token reporting prerequisites. Report only capabilities actually installed and tested. Keep source/version and installation evidence private.

Keep the user's short CTO summaries. Include material unchecked behavior or risks where relevant. This user preference takes precedence over routine per-message boilerplate. Do not present the upstream author's benchmark percentages as this team's measured token, time, or cost savings. No local savings claim follows merely from installation.
